## Known limits & open non-founder items
- **Stickers:** V-ST-1 (option B), V-ST-2 (401 refresh retry + real media content download in `AdapterContractTests.stickers`) and V-ST-3 (legacy `im.ponies.room_emotes`/`emote_rooms` in `legacyPacks`) are verified against `infra/dev`; pack editing/deleting (rename, add/delete stickers, delete pack) is implemented in `StickerPackManagementPort`/`StickerPackManager`/`StickerPackDetailView`. Not built (out of v1 scope): `im.ponies.user_emotes` (pack without a room) and non-empty-key legacy packs in rooms over 1,000 members.
- **Large-account classic-sync cost (D74 / R-18):** under classic `/sync` (`syncOnceV2`), `SyncSettingsV2` in the pinned SDK (`26.11.17`, F-FFI-23) exposes no filter (no `lazy_load_members`, no timeline limit); bounded per-room summary rebuilds (max 8, single `roomInfo()`, R-19) are in place, while adding a filter to `SyncSettingsV2` awaits an upstream SDK change (HANDOFF §5 R-18).
- **Room info member count under classic sync:** `Room.joinedMembersCount()` reports `0` under classic sync on `infra/dev`, so `RoomDetailsViewModel.joinedMemberCount` uses `max(details.joinedMemberCount, loadedJoinedMembers)` (up to the paged limit). Pull-to-refresh (`RoomDetailsViewModel.refresh()`) updates permissions cleanly when a newly created room opens before power levels arrive from sync (TD-13 removed the 1.5 s sleep workaround).
- **Bot cards & ticking:** template parsers (`TodoListV1`, `TaskAddedV1`, `ReminderSetV1`, `TaskDoneV1`, `TaskDeletedV1`) follow SOURCES F-BOT-3/4 and the spec; unrecognised messages from allowlisted bots are counted per launch by `UnrecognisedBotMessages` in Settings → Diagnostics. Only the task owner's 👍 reaction is acted on by the bot (Q-BOT-OWNER; others time out after 2 minutes with "No response from bot"). Not yet verified against a live production bot instance.
- **Notification defaults:** `setDefaultRoomNotificationMode(.mute)` for a global chat category fails with `UnableToUpdatePushRule` in the SDK against `infra/dev`, so Settings → Notifications offers `All messages` and `Mentions and keywords` for category defaults (per-room mute works and is verified by `roomManagement` and `ServerReadStateScenarioTests` S10).

## Local environment & test-harness notes
- **Simulator destination on this Mac:** default `iPhone 17` in `scripts/prepush.sh` / `scripts/contract-test.sh` is overridden via `HALO_SIM="iPhone Air"`.
- **Contract tests (`scripts/contract-test.sh`):** settings live in `~/.config/halo-dev/contract.env` (`TEST_RUNNER_HALO_DEV_*`, server `http://localhost:8008`), generated by `infra/dev/create-fixtures.py` (run with `--new-e2ee` before `encryption`). Contract tests are serialized, leave the rooms and sign out the devices they create (the `.cleansUp` trait, also after a failure; `contract-test.sh` fails a run that left something, `infra/dev/leftovers.py`), and don't depend on how many rooms the shared account has. Offline-send (`AdapterContractTests.offlineSend`) runs via `scripts/contract-offline-test.sh`.
- **Docker CLI on this Mac:** if the default credential helper (`osxkeychain`) hangs on `docker compose`, use a throwaway `DOCKER_CONFIG` directory with `docker exec` / `docker restart`.
